# B00.CH05 — Definition set III: caps on wealth/claims (W-MAX)

This chapter defines the canonical **W-MAX** cap: a binding limit on **wealth/claims/rights (W)** as a **stock**
variable. W-MAX is an order instrument: it limits durable claim accumulation and therefore constrains the ability
to sustain **claim stacks**, **rent-seeking**, and **power** that translate into extraction (**E**) and life-world
pressure (L↑, R/B↓).

W-MAX is not a slogan (“tax the rich”). It is a **formal cap regime** with:
- a canonical definition of **W** (economic claim position over future flows and assets),
- a cap base (**W-base**) that includes economic equivalents and control rights,
- look-through consolidation under **UBC** (control/benefit/block) across vehicles and structures,
- valuation discipline (hierarchy + conservatism + anti–window dressing),
- cap mechanics (trigger, remedy options, duties, fail-closed),
- a traceable reallocation path **W-MAX → C** (commons build/maintenance) under ΔG evidence,
- cross-border coherence and anti-avoidance,
- minimum disclosure + audit requirements,
- enforcement, dispute, and hard stops.

## How to use this chapter

- If you are **writing any later chapter**: import W, W-base, UBC look-through, valuation hierarchy, and cap mechanics
  from here; do not redefine locally.
- If you are **building datasets/pipelines**: implement the W-base + UBC graph consolidation and valuation rules;
  treat economic equivalents and control rights as first-class cap objects.
- If you are **auditing**: require reproducible valuation and look-through derivations; test for leaky bases,
  nominee dispersion, and window dressing; enforce fail-closed where W is uncertain.
- If you are **implementing I-MAX, ΔM or R/B floors**: treat W-MAX as the stock-side brake that prevents claim
  accumulation from regenerating E and inflating essentials burdens (L).

## Status

This chapter should remain stable across versions because it defines a core cap instrument and its measurement and
enforcement interface. Changes here are high-impact and typically imply major version implications:
- altered W definition or W-base inclusion rules (especially equivalents and control rights);
- altered UBC consolidation or graph evaluation rules;
- altered valuation hierarchy, haircuts, or anti–window dressing rules;
- altered cap mechanics/remedy set or fail-closed posture;
- altered cross-border or anti-avoidance equivalence rules.

A “cap” with a leaky base, black-box valuation, discretionary exceptions, or unenforceable look-through is non-conform
by default and cannot support an OBA compatibility claim.
