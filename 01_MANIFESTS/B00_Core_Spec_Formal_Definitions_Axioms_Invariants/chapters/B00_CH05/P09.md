# B00.CH05.P09 — Reallocation path: W-MAX → C (commons build-up/maintenance)

This paragraph defines the canonical reallocation path by which W-MAX remedies (skimming, conversion, or lockbox
outcomes) may be allocated into **C (commons contribution)**. The purpose is to ensure that cap enforcement can
produce structural order gains (L↓, R/B↑) only when reallocation is **real**, **traceable**, and **anti-capture**.

Key principle: reallocation is not “C” because it is called public or charitable. It counts as C only when it
produces **verifiable commons capacity** (ΔG↑ or ΔG stabilisation) under a governance regime that prevents
re-privatisation and owner backflow.

---

## B00.CH05.P09.S01 — Admissibility: reallocation counts as C only with traceable ΔG output

A W-MAX-derived allocation counts as **C** only if it meets admissibility conditions that make it auditable as
commons build-up/maintenance.

Canonical admissibility requirements (all required):

1) **Traceable source:** the allocation is traceably linked to a cap event (breach → remedy → amount).
2) **Defined commons object:** the destination is a defined commons/public option object with an explicit access and
   maintenance regime (not merely “public spending”).
3) **ΔG metric linkage:** the project has defined ΔG metrics (capacity, access, reliability, maintenance state) and
   reports outputs against them.
4) **Non-appropriability:** governance prevents conversion into a toll gate or private capture.
5) **Additionality:** allocation must be additional (not replacing existing commons budgets while leaving net ΔG
   unchanged), unless explicitly treated as substitution with disclosed impact.

ΔG may be build-up (ΔG↑) or stabilisation (preventing degradation), but must be measurable.

### Conformance requirements (binding)

- W-MAX reallocation MUST not be counted as C without an explicit ΔG output specification and reporting method.
- If ΔG outputs cannot be audited, the allocation may be recorded fiscally, but it cannot certify an OBA C-claim.

---

## B00.CH05.P09.S02 — Forbidden reallocation: pseudo-commons, captured institutions, backflow to owner

Certain “reallocations” are forbidden because they preserve private dominance or create cosmetic commons labels.

Forbidden patterns include (non-exhaustive):

- **Pseudo-commons:** projects branded as public/commons but operating with exclusion, discrimination, or toll-gate
  access regimes (no credible public option).
- **Captured institutions:** allocation routed to institutions controlled or effectively influenced by the same
  cap-subjects (directly or via nominees), enabling self-dealing and agenda control.
- **Backflow to owner:** any routing that returns value to the original subject (or their controlled household/vehicles)
  via contracts, procurement, management fees, licensing, rent extraction, or asset buybacks.
- **Circular financing:** “donate” then receive privileged concessions, contracts, or regulatory advantages that
  recreate claim stacks.
- **Opacity laundering:** intermediaries that prevent tracing (black-box foundations, off-budget vehicles).

Canonical principle: if reallocation preserves the same control/benefit structure in substance, it is not C.

### Conformance requirements (binding)

- Any reallocation channel MUST include anti-capture checks (UBC look-through on intermediaries, procurement controls).
- Evidence of backflow or capture voids C admissibility for that allocation and triggers enforcement escalation.

---

## B00.CH05.P09.S03 — Destination rules: essentials/infra, maintenance-first, lifecycle obligation

To maximize structural order effects, admissible W-MAX → C allocation must follow destination discipline.

Canonical destination priorities (binding as an ordering principle, parameterized by regime):

1) **Essentials and public option capacity** (housing, energy, health, mobility, basic connectivity, basic food systems)
   where L pressure is structural.
2) **Infrastructure and resilience** that stabilizes service levels and reduces volatility pass-through into L.
3) **Commons maintenance** (ΔG stabilisation): repairability, service continuity, lifecycle upkeep obligations.

Maintenance-first rule:
- where existing commons assets are degrading, maintenance and service-level stabilization takes priority over new
  build if the ΔG effect per unit is higher and prevents future L inflation.

Lifecycle obligation:
- allocations must include lifecycle cost provisioning and maintenance governance; otherwise projects become future
  extraction sites via degradation and privatized “rescue” contracts.

### Conformance requirements (binding)

- Any W-MAX → C allocation claiming order benefit MUST state destination category and show how it plausibly reduces L
  or stabilizes volatility (link to CH04).
- Projects without maintenance/lifecycle provisioning are non-conform for C credit unless explicitly bounded and
  treated as temporary with disclosed risk.

## B00.CH05.P09.S04 — Audit trail: from cap event to project, costs, outputs and ΔG metrics

C credit requires a full audit trail from cap enforcement to measurable commons outputs.

Minimum audit trail requirements:

- **Cap event record:** subject ID (within privacy constraints), consolidated W calculation snapshot, breach amount,
  remedy chosen/applied, valuation basis and uncertainty.
- **Transfer record:** amounts transferred, timing, intermediaries, legal instruments, restrictions.
- **Project record:** destination project ID, governance regime, access regime, maintenance obligations.
- **Cost accounting:** spend categories, procurement contracts, beneficiaries, anti-backflow controls.
- **Outputs:** ΔG metrics (capacity created/maintained, access expansion, service reliability), with measurement method.
- **Outcome linkage:** where possible, link to L reduction and R/B profile effects with uncertainty.

Audit trail must be reproducible and versioned; missing links void C classification for the allocation.

### Conformance requirements (binding)

- If the chain cap event → allocation → project → ΔG output cannot be reproduced, the allocation cannot be counted as C.
- Any material audit gap triggers fail-closed classification for the affected allocation and may suspend compatibility
  claims for the channel until remediation.
