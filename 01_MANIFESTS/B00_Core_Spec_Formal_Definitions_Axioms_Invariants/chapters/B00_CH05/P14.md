# B00.CH05.P14 — Enforcement and dispute regime

This paragraph defines the canonical **enforcement chain** and **dispute regime** for W-MAX. A cap is not an order
instrument unless it is enforceable under adversarial incentives. Enforcement must be:
- operationally explicit (chain defined end-to-end),
- auditable (reproducible records),
- contestable (due process),
- and non-gameable (appeal cannot function as delay-as-avoidance).

The dispute regime must allow correction of errors without enabling semantic drift or bespoke deals.

---

## B00.CH05.P14.S01 — Enforcement chain: detection → assessment → cap event → remedy → audit

Canonical enforcement is a staged chain. Each stage produces auditable artifacts.

### Stage 1 — Detection
- triggers: periodic reporting + event-driven triggers + anomaly signals (CH05.P13, CH05.P05, CH05.P08).
- detection includes identifying potential breach and/or opacity red flags (missing nodes, suspicious transfers).

### Stage 2 — Assessment
- consolidate W via UBC graph (CH05.P06),
- value W via valuation hierarchy + haircuts/bands (CH05.P05),
- apply netting via recognized liabilities only (CH05.P04),
- compute W_consolidated and compare to W-MAX parameters (CH05.P07),
- record uncertainty bands and any fail-closed provisional treatment.

### Stage 3 — Cap event declaration
- if W > W-MAX (or if fail-closed uncertainty triggers provisional enforcement), declare a cap event.
- cap event record includes: breach amount, valuation snapshot, consolidation graph hash/version, and trigger basis.

### Stage 4 — Remedy execution
- apply canonical remedy options (skimming, conversion, lockbox, reallocation) per regime (CH05.P08–P09).
- enforce timing and sequencing rules; restrict remedy selection that preserves control/benefit in substance.

### Stage 5 — Audit and closure
- verify remedy effect (post-remedy W ≤ threshold or skim function executed),
- verify traceability of reallocations (if any) and anti-backflow controls (CH05.P09),
- publish required aggregates/method updates and log any requalification.

Each stage must be logged; missing stages are non-auditable and therefore non-conform.

### Conformance requirements (binding)

- A W-MAX regime MUST define and operate the full enforcement chain; “cap exists” without operational chain is non-conform.
- Each cap event MUST be reproducible from published method tags + audit artifacts; otherwise outcomes are discretionary.

## B00.CH05.P14.S02 — Objection/appeal: contestability without delay-as-avoidance

Subjects must be able to contest errors (valuation, consolidation, classification). However, appeals are a major
avoidance surface if they suspend enforcement indefinitely.

Canonical appeal regime requirements:

- **Contestability:** subject can object to:
  - valuation inputs/method,
  - UBC consolidation edges,
  - liability recognition status,
  - requalification decisions,
  - remedy calculation.
- **Bounded timelines:** objections must be filed within defined windows; authorities must respond within defined
  timelines.
- **No automatic suspension:** filing an objection does not automatically halt enforcement unless a defined threshold
  of prima facie error is met.
- **Interim enforcement:** where dispute exists, conservative interim treatment applies (escrow/lockbox, provisional
  skimming, or conservative valuation) to prevent delay-as-avoidance.
- **Evidence burden:** subject bears burden to provide documentation for exclusions, valuations, independence claims.

The dispute mechanism must preserve semantic closure: it cannot become a negotiation channel for bespoke exceptions.

### Conformance requirements (binding)

- Any regime where appeal automatically suspends enforcement without interim controls is leaky and non-conform.
- Dispute outcomes must be logged and must not redefine canonical rules; if rules change, it is a version change.

## B00.CH05.P14.S03 — Proportionality and legal protection: procedural guarantees (canonical)

W-MAX enforcement must include procedural guarantees to avoid arbitrary power and ensure legitimacy, while remaining
robust against gaming.

Canonical procedural guarantees include (non-exhaustive):

- **Notice and explanation:** subjects receive clear cap-event basis (method tags, valuation basis, consolidation edges).
- **Right to be heard:** subject can submit evidence and challenge inputs.
- **Independent review:** disputed decisions can be reviewed by an independent adjudicator under declared criteria.
- **Proportionality:** sanctions/escalations are proportional to severity and intent (negligent error vs obstruction).
- **Consistency and non-discrimination:** rules apply uniformly; selective enforcement is non-conform and signals capture.
- **Data protection:** disclosure is limited to what is necessary for enforcement and audit (privacy minimalism), with
  secure handling, without creating exemption.

These guarantees are necessary for a durable cap regime; without them, enforcement becomes politically fragile or
capturable.

### Conformance requirements (binding)

- A W-MAX regime MUST specify procedural guarantees and apply them consistently; arbitrary enforcement undermines
  auditability and legitimacy.
- Proportionality must not become discretion to exempt; guarantees protect rights but do not permit cap bypass.

## B00.CH05.P14.S04 — Hard stops: refusal to disclose, black-box valuation, obstruction → non-conform status

Certain conditions trigger immediate non-conform status and enforcement escalation because they destroy auditability.

Canonical hard stops include (non-exhaustive):

- **Refusal to disclose** required minimum dataset elements (assets, vehicles, beneficial relations).
- **Black-box valuation** (undisclosed models, unverifiable inputs, refusal of independent valuation where required).
- **Obstruction** (destroying records, nominee hiding, sham restructures, non-cooperation with audits).
- **Repeat avoidance patterns** showing intentional bypass (window dressing, circular liabilities, repeated opacity).

Hard-stop posture:
- enforce fail-closed (conservative inclusion, provisional remedies, lockbox),
- escalate sanctions/penalties proportionally,
- suspend any OBA compatibility claim for the subject/channel until remediation and verified disclosure occur.

### Conformance requirements (binding)

- Any W-MAX regime MUST define hard stops and must treat refusal/black-box/obstruction as non-conform by default.
- If a regime tolerates black-box valuation or non-disclosure while asserting compliance, it is non-conform at the
  regime level (cap exists only as text, not as enforceable order instrument).
