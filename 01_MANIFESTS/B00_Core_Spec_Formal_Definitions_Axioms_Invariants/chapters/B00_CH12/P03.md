# B00.CH12.P03 — Measurement methods: definitions, procedures and minimum metadata

This paragraph defines the **minimum requirements for measurement methods** used in OBA claims. Methods must be **registered**,
**versioned**, and **reproducible**, with metadata sufficient to trace every published statistic back to sources and procedures. The
method layer may operationalize canonical objects, but must not redefine them.

---

## B00.CH12.P03.S01 — Method registration: definition-set ID, version, measurement procedure, source data, sampling

Every measurement method used for compatibility evaluation MUST be registered as a versioned artifact, explicitly bound to the
definition set it implements.

### Mandatory method registration fields (minimum)
- **definition_set_id**
- **definition_set_version**
- **method_id** and **method_version**
- **measurement procedure**: step-by-step specification (variables, transformations, aggregation, thresholds)
- **source data specification**:
  - dataset identifiers, provenance, access route,
  - collection frequency and timestamps,
  - units and encoding conventions
- **sampling specification** (if sampled):
  - sampling frame, inclusion/exclusion rules,
  - sample size, weights, non-response handling,
  - variance estimation approach
- **coverage statement**:
  - population/sector scope, jurisdiction scope,
  - known blind spots and exclusions

### Conformance requirements (binding)
- Any metric used in an OBA compatibility claim MUST reference a registered method artifact.
- If method registration is missing or incomplete, dependent claims MUST be treated as **non-conform** (fail-closed).
- Silent method changes are forbidden; any method change MUST produce a new version and changelog entry.

## B00.CH12.P03.S02 — Data minimalism: only data needed for order evaluation (link to Book 4)

OBA requires **data minimalism**: collect and process only the data necessary to evaluate order properties and enforce constraints.
Excess data collection increases surveillance and capture risk without improving auditability.

### Minimalism principles
- **Purpose limitation**: each data element must be justified by a specific invariant, parameter, or audit requirement.
- **Least granularity**: use the coarsest granularity that still supports required observables and distribution checks.
- **Separation of concerns**: keep identity, sensitive attributes, and behavioral exhaust out of compatibility pipelines unless
  canonically required and justified with strict safeguards.

### Conformance requirements (binding)
- Any measurement system MUST publish a data inventory with justification mapping: **data field → required observable/test**.
- Data fields without a binding justification MUST be removed from the measurement pipeline.
- Where privacy-preserving publication is required, the method MUST specify the redaction/anonymisation strategy without breaking
  auditability requirements.

## B00.CH12.P03.S03 — Normalisation: units, deflators, price indices, time resolution (canonical)

Comparable measurement requires canonical normalisation: common units, deflation conventions, index references, and time resolutions.

### Normalisation requirements (minimum)
- **Units**: explicit units for all quantities; currency and base year (if monetary).
- **Deflators / price indices**: declared index source, base period, update cadence, and application rule.
- **Time resolution**: declared window (monthly/quarterly/annual) and alignment rules (accrual vs cash, lag handling).
- **Cohort alignment**: consistent cohort definitions and reclassification rules over time.

### Conformance requirements (binding)
- Any published metric used in compatibility evaluation MUST declare its normalisation conventions in method metadata.
- Mixing indices, base years, or time windows without a declared reconciliation rule is forbidden and invalidates comparability claims.
- Any change in normalisation conventions MUST be versioned and may require restatement/bridging to preserve semantic continuity.

## B00.CH12.P03.S04 — Consistency: reconciliation with accounting/national accounts and microdata

OBA measurement must be internally consistent and externally reconcilable. Reported aggregates should reconcile with accounting and
macro statistics where applicable, and microdata should reconcile with published summaries within defined bands.

### Consistency requirements (minimum)
- **Accounting reconciliation**: mappings between measurement categories and standard accounting categories; coverage differences disclosed.
- **National accounts reconciliation** (where applicable): bridge tables to macro aggregates; discrepancies explained.
- **Micro-to-macro coherence**: microdata aggregation should reproduce published totals within declared tolerance bands.
- **Double-count prevention**: rules preventing duplicate flows across entities or channels.

### Conformance requirements (binding)
- Implementations MUST publish reconciliation tables (or equivalent artifacts) that show how OBA observables map to standard accounts.
- Unexplained reconciliation gaps beyond declared tolerance bands MUST trigger a measurement dispute review and may trigger suspension
  of dependent compatibility status (fail-closed).
