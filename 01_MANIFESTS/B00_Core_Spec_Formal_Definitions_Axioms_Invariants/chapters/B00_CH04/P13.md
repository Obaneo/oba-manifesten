# B00.CH04.P13 — Auditability and reproducibility

This paragraph defines the auditability and reproducibility requirements for any OBA-grade computation and use of
Definition set II (**B, T, N, L, R**, cohort **R/B** profiles, and **R/B ≥ α** claims).

R/B is an order indicator only if it is **reproducible** from recorded inputs and **reconcilable** from micro to
macro. If outputs cannot be independently reproduced, or if reconciliation fails without disclosed reasons, then
the evaluation is non-conform for OBA purposes.

---

## B00.CH04.P13.S01 — Reconciliation with national accounts and microdata (consistency requirements)

Any implementation must support **micro→macro consistency** between:
- microdata-based B/T/L/R computations (households/entities), and
- macro aggregates (national accounts, sector accounts, tax aggregates, essentials price indices), within stated
  coverage and measurement error bounds.

Canonical reconciliation requirements:

- **Identity consistency:** N = B − T and R = N − L must hold at micro and aggregate levels (subject to disclosed
  rounding/coverage).
- **Boundary consistency:** the unit boundary used for micro computations must map cleanly to macro accounting
  boundaries (households, firms, government) with explicit consolidation rules.
- **Component mapping:** micro components of B and T must map to macro categories (wages, transfers, taxes, etc.);
  discrepancies must be explained (timing, underreporting, coverage).
- **Essentials alignment:** L baselines must align with published price regimes/indices (or justify deviations)
  and must not be defined ad hoc per cohort.

Reconciliation is not a perfection demand; it is a transparency demand: unexplained gaps are where gaming hides.

### Conformance requirements (binding)

- Implementations MUST publish reconciliation statements and residuals (gaps) with explanations and uncertainty.
- If reconciliation fails materially and cannot be explained, dependent OBA claims must fail closed or be limited to
  reconciled components only.

## B00.CH04.P13.S02 — Anti-gaming: classification audits, sampling, anomaly detection (L inflation, shadow fees)

R/B systems are gameable. Auditability therefore requires explicit **anti-gaming** controls.

Canonical anti-gaming controls include (non-exhaustive):

- **Classification audits:** check strict T and L rules are applied consistently; detect relabeling attempts (L→T,
  optional→essential, “voluntary” laundering).
- **Sampling and verification:** sample micro units/contracts to verify burden and receipt classification against
  source records; detect systematic bias.
- **Anomaly detection:** detect suspicious patterns such as:
  - sudden L decreases without price regime change,
  - sudden B increases via boundary/transfer counting changes,
  - essentials baskets drifting upward (upgrade inflation),
  - shadow fees emerging in essentials (new mandatory add-ons),
  - divergence between micro-reported burdens and macro price indices.
- **Fee-stack surveillance in essentials:** monitor housing/energy/health for new fee layers that raise effective L.

Anti-gaming is part of conformance: if controls are absent, the system is not robust enough to carry an OBA claim.

### Conformance requirements (binding)

- Any OBA-grade implementation MUST include explicit anti-gaming tests and publish their existence (and high-level
  findings) as part of the audit package.
- If anomaly signals indicate likely L inflation or shadow-fee growth and the system does not escalate, it is
  non-conform for claims relying on the affected period/domain.

## B00.CH04.P13.S03 — Publication requirement: methods, definition-set ID, changelog, revision policy

Auditability requires publication of sufficient method detail to reproduce outputs.

Minimum publication package must include:

- **Definition-set ID and version:** explicit reference to the canon version used (CH04 definition set).
- **Method specification:** how B/T/L are measured, parameter regimes (essentials basket, indices), smoothing rules,
  cohort definitions and weights, α regime.
- **Uncertainty and coverage:** bands, missingness, modeled vs observed shares.
- **Changelog:** any changes in definitions, parameters, indices, cohort definitions, or data sources.
- **Revision policy:** how restatements occur, how comparability is handled, and what triggers a revision.

Without a revision policy, systems can silently rewrite history (“passing by restatement”) and undermine semantic
closure.

### Conformance requirements (binding)

- OBA claims MUST reference a published method package and definition-set ID; unpublished or proprietary methods are
  non-conform for OBA-grade evaluation.
- Silent methodology changes without changelog and restatement notes are non-conform.

## B00.CH04.P13.S04 — Dispute protocol: objection/appeal, corrections, restatements without semantic break

Because R/B outputs can be contested (classification of essentials, boundary choices, indices, α regime), OBA requires
a canonical dispute protocol that preserves semantic stability.

Minimum dispute protocol includes:

- **Objection/appeal intake:** who can object, what evidence is admissible, and how objections are logged.
- **Adjudication procedure:** defined authority, criteria, and timelines; separation of technical correction from
  political preference.
- **Corrections:** when errors are found (classification mistakes, index errors, boundary misapplication), corrections
  must be made with full audit trail.
- **Restatements without semantic break:** restatements must not redefine quantities silently; if semantics change,
  it is a version change and must be treated as such (non-comparable unless mapped).
- **Public record:** decisions, corrections, and restatements must be recorded and versioned.

### Conformance requirements (binding)

- Any system claiming OBA-grade R/B evaluation MUST have a dispute protocol; absence is non-conform because it permits
  unchecked drift and capture.
- If corrections occur, they MUST be logged and restated transparently; “quiet fixes” are non-conform by default.
