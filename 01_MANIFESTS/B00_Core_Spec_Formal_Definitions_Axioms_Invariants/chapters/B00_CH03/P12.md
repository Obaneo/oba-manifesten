# B00.CH03.P12 — Failure modes and hard stops

This paragraph defines canonical **failure modes** and **hard stops** for P/E/C classification. These are not
“best practice” suggestions; they are **non-conformance conditions**. If a hard stop is triggered, the affected
component cannot be used to support an OBA conformance/compatibility claim.

The point is adversarial robustness: P/E/C must remain valid under strategic behavior, relabeling, and opacity.

---

## B00.CH03.P12.S01 — OBA-washing via semantics: “service”/“innovation” as cover for E

A primary failure mode is semantic laundering: relabeling extractive tolls as “service”, “innovation”, “premium”,
“efficiency”, “market rate”, or “value-based pricing” without changing the underlying power/lock-in mechanism.

Canonical indicators of semantic OBA-washing include (non-exhaustive):

- classification changes driven by labels rather than by measurable changes in deliverables, costs, or exit power;
- claims of “innovation” without auditable novelty, contestability trajectory, or time-boundedness;
- rebranding of fees (admin/convenience) without changes in fee necessity or bundling constraints;
- “public” or “green” narratives used to mask continued toll extraction in essentials.

### Hard stop condition (binding)

- If P/E/C classification depends on rhetorical labels rather than auditable functional criteria, the classification
  is non-conform for OBA-critical evaluation.

---

## B00.CH03.P12.S02 — Gaming the classification: bundling, cross-subsidies, shadow prices

Strategic actors can game classification by manipulating observability and allocation of price components.

Canonical gaming tactics include (non-exhaustive):

- **Bundling/tying:** hiding tolls inside composite prices; making “optional” add-ons de facto mandatory.
- **Cross-subsidies:** subsidizing visible prices while extracting via hidden channels (data/attention, penalties,
  lock-in renewals), or shifting extraction upstream/downstream in the chain.
- **Shadow prices:** extracting via non-salient charges (late fees, cancellation fees, default traps) or via
  degraded service unless paid upgrades are purchased.
- **Chain laundering:** moving extraction into internal transfer pricing, IP shells, or intermediary layers to
  evade scrutiny and attribution.

### Hard stop condition (binding)

- If an implementation does not apply decomposition and chain/fee-stack detection where these tactics are plausible,
  it is non-conform for OBA-grade use on the affected domain/flows.

---

## B00.CH03.P12.S03 — Black-box classification is non-conform (non-auditable)

P/E/C classification must be **auditable**. A black-box classifier—human or machine—that cannot provide a
reproducible derivation is non-conform where OBA claims depend on it.

Black-box patterns include (non-exhaustive):

- undisclosed heuristics (“expert judgement”) without recorded inputs and decision rules;
- ML/AI outputs without inspectable feature inputs, thresholds, and rule mapping;
- proprietary scoring systems where results cannot be independently reproduced;
- classifications that cannot be reconciled micro→macro because micro audit trails are absent.

### Hard stop condition (binding)

- Any P/E/C output used to support an OBA conformance/compatibility claim MUST have a reproducible audit trail.
  If not, the affected component is non-conform and cannot certify an OBA claim.

---

## B00.CH03.P12.S04 — Fail-closed: missing data/controllability → no OBA claim on that component

OBA requires **fail-closed** discipline: missingness must not create free credit.

Canonical fail-closed rule:

- If required data is missing such that E could be hidden (fees, lock-in terms, chain layers, hidden price domains),
  then the component MUST be:
  - classified conservatively as **E**, OR
  - marked **unknown/non-conform** (non-certifying).
- If controllability is absent (no ability to enforce the claimed access/commons regime, no audit leverage), then
  the claimed C or P properties cannot be credited for OBA claims.

Fail-closed is especially binding in:
- essentials (housing/energy/health),
- platform/intermediary fee stacks,
- finance (refinancing lock, penalty layers),
- data/advertising hidden-price environments.

### Hard stop condition (binding)

- If an implementation cannot observe or control the variables required for classification in a domain, it MUST NOT
  claim OBA conformance on that domain/component. Coverage limits MUST be disclosed; omission is non-conform.
