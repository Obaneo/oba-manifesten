# B00.CH03.P06 — Decomposition: a single payment can contain P+E (and sometimes C)

This paragraph defines the canonical **decomposition rule**: a single observed payment (or obligation) may contain
multiple components—typically **P + E**, and sometimes **C**—and OBA-grade evaluation requires splitting those
components where they materially affect classification, R/B impacts, caps relevance, or ΔM compliance.

Decomposition is the enforcement mechanism for “functional, not rhetorical” classification. Without it,
implementations can hide extraction inside bundled prices, opaque tariffs, or chained intermediaries.

Normative posture is conservative: if splitting is required for auditability but cannot be performed due to missing
inputs, the disputed component MUST be treated as **unknown/non-conform** or conservatively as **E**, and dependent
claims MUST fail closed.

---

## B00.CH03.P06.S01 — Split rule: functional component (P) + toll component (E)

### Canonical split

For any flow amount **A**, define a decomposition:

- **A = P + E (+ C when applicable)**

Where:
- **P** is the functional remuneration consistent with deliverable function/value and bounded normal margin;
- **E** is the residual toll component sustained by power/lock-in/claim stacking/information asymmetry;
- **C** is the portion that is a traceable allocation to commons capacity or access/maintenance duties (when
  explicitly present in the payment structure or contract).

### Baseline splitting logic (canonical)

1) Identify the deliverable function(s) and required service level(s).  
2) Establish the functional cost basis (or auditable proxy) and bounded normal margin.  
3) Assign **P = functional costs + bounded margin** (within declared uncertainty).  
4) Assign **E = A − P** for the remaining amount not justified by function.  
5) If a portion is explicitly earmarked/structured as commons allocation under enforceable regime, split **C**.

Where the cost basis cannot be established, the split MUST use bounded ranges and conservative escalation.

### Conformance requirements (binding)

- Any OBA-critical classification MUST support decomposition where a payment plausibly contains toll extraction.
- If the split depends on assumptions (e.g., cost proxies, margin bounds), those assumptions MUST be declared and
  reproducible; otherwise the split is non-auditable and MUST fail closed.

## B00.CH03.P06.S02 — Tariff and bundle decomposition: licences, subscriptions, platform fees, add-ons

Tariffs and bundles are primary carriers of hidden E. Decomposition MUST therefore be applied to:

- **Licences / subscriptions:** base access vs paywalled layers, renewal traps, cancellation friction,
  forced upgrades, “feature gating”.
- **Platform fees:** take rates, listing fees, payment processing, ranking/visibility charges, API access,
  data access, “optional” add-ons required in practice.
- **Add-ons and surcharges:** “service fees”, “convenience fees”, “mandatory insurance”, “admin fees”,
  device rental tied to service, proprietary consumables.
- **Two-sided/hidden price:** where the user’s monetary payment is low but attention/data extraction is the true
  price; the hidden-price component must be modeled as E if it functions as a toll.

Canonical approach:
- Separate baseline functional delivery from access-control rents.
- Treat fees that are unavoidable to obtain a basic function as part of the effective price, not as “optional”.
- If the bundle prevents unbundling without functional necessity, the bundle premium is presumptive E.

### Conformance requirements (binding)

- A bundle/tariff classification MUST disclose the bundle structure (components, gating rules, renewal/cancel terms)
  as metadata sufficient to reproduce the split.
- If an “add-on” is de facto mandatory (through design or contract), it MUST be included in A and evaluated for E.

## B00.CH03.P06.S03 — Vertical chain: pass-through, internal fees, transfer pricing splitting

In vertical chains, the observed payment may embed multiple upstream claims. Decomposition must therefore support:

- **Pass-through identification:** separate pass-through taxes, regulated charges, and true cost pass-through from
  markups and toll layers.
- **Intermediary layers:** distributor fees, franchising royalties, procurement gate tolls, clearing/settlement fees.
- **Internal fees and transfer pricing:** intra-group charges that move surplus to low-visibility nodes (IP holding,
  financing arms, platform subsidiaries).
- **Bundled finance:** embedded credit cost, penalty pricing, refinancing spreads.

Canonical splitting requires chain attribution:
- identify each layer’s functional service (if any),
- assign bounded P to each functional layer,
- assign residuals that persist due to control/choke/opacity to E,
- prevent double counting by tying each component to a specific layer and contract.

### Conformance requirements (binding)

- Where chain structure materially affects classification, implementations MUST record chain metadata sufficient to
  attribute P/E across layers; otherwise OBA claims fail closed on affected flows.
- If internal fees are opaque and prevent attribution, the un-attributable residual MUST be treated as E or unknown
  (non-certifying) under conservative discipline.

## B00.CH03.P06.S04 — Rules against double extraction: fee stacks and cascade detection

Decomposition must include explicit defenses against **double extraction**: multiple parties extracting rent on the
same underlying function, often hidden via fee stacks and cascading tolls.

Canonical detection rules include (non-exhaustive):

- **Fee-stack detection:** identify multiple percentage-based or fixed fees applied sequentially to the same base
  (platform → payment processor → affiliate → distributor).
- **Cascade detection:** detect when one fee becomes the base for the next (fees-on-fees), amplifying extraction.
- **Duplicate functionality test:** if two layers claim to provide the same functional service without incremental
  value, the redundant layer is presumptive E.
- **Non-removability test:** if a fee layer cannot be avoided without losing basic access, treat it as part of the
  effective toll.

Classification discipline:
- assign P once per distinct functional service;
- assign E to stacked residuals not justified by incremental function;
- ensure the sum of split components reconciles to the observed total without double counting.

### Conformance requirements (binding)

- Implementations MUST include explicit fee-stack/cascade checks where platform/intermediary structures exist.
- If fee-stack structure is not observable (missing data), the classifier MUST not assume absence; it MUST escalate
  (conservative E or non-conform/unknown) and disclose the limitation.
