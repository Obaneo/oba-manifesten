# B00.CH03.P04 — Definition of C: commons contribution (build and maintenance)

This paragraph defines **C (commons contribution)** as the component of a flow (or duty) that allocates resources
to **public/commons capacity**: building it, maintaining it, or guaranteeing access to it under a regime that
reduces structural dependence and claim-layer pressure.

C is functional: it is determined by **order effects** (capacity ΔG increase or stabilisation; access and
non-discrimination properties; reduced lock-in and reduced burdens), not by branding (“CSR”), intent narratives,
or ownership labels.

C is not “anything done by the state” and not “anything non-profit”. A private entity can generate C (e.g., open
standards, non-discriminatory access, lifecycle maintenance obligations) and a public entity can fail to generate
C if it operates as an extractive gate with toll mechanics.

Where a single payment includes P, E, and/or C components, decomposition applies: C must be separated where
traceable and auditable.

---

## B00.CH03.P04.S01 — C as allocation to public/commons capacity (ΔG↑ or ΔG stabilisation)

A component is **C** when it is an allocation to **commons capacity** that either:
- increases capacity (**ΔG↑**), or
- stabilises capacity over time (**ΔG stabilisation**) by preventing degradation, capture, or under-provision.

Commons capacity includes (non-exhaustive):
- public option infrastructures (housing, energy, health, education, mobility, digital identity, payments);
- shared physical and digital infrastructure (networks, standards, open tooling, interoperability layers);
- resilience and maintenance funds that preserve long-term capacity and service levels;
- governance and enforcement capacities that keep access non-extractive (anti-capture, auditability).

The defining condition is that the allocation is **structurally oriented**: it changes the feasible set for
actors by increasing contestable access and reducing dependency, rather than merely compensating individuals
within an unchanged extractive structure.

### Conformance requirements (binding)

- A claimed C component MUST be traceable to a defined commons object/capacity and to a measurable ΔG effect (increase
  or stabilisation), or to a clearly specified stabilisation mechanism.
- If the allocation can be reversed, privately appropriated, or transformed into a toll gate without enforceable
  safeguards, it cannot be counted as C for OBA-critical claims.

---

## B00.CH03.P04.S02 — C as access: public option, open access, non-discrimination

C includes the component of arrangements that create or guarantee **access** on commons terms:
- public option availability (an exit that disciplines private tolls),
- open access under stated rules,
- non-discrimination and equal treatment for equivalent cases,
- portability/interoperability features that preserve real exit and contestability.

“Access as C” is not charity. It is an order mechanism: it expands the option set and reduces the ability of
gatekeepers to impose extraction.

Access can be implemented through:
- zero/low-fee public option provision,
- regulated access obligations with audited compliance,
- open standards/API access preventing ecosystem captivity,
- anti-exclusion and anti-foreclosure rules that preserve contestability.

### Conformance requirements (binding)

- Any C claim based on access MUST specify the access regime: eligibility, pricing rules (if any), service level,
  portability/interoperability conditions, and enforcement/audit mechanisms.
- If access is nominal but exit is not credible (e.g., hidden frictions, capacity scarcity, discrimination by design),
  the claim MUST be downgraded; ambiguous access claims fail closed.

---

## B00.CH03.P04.S03 — C as maintenance duty: lifecycle, service levels, repairability

C includes **maintenance duties** that are structured as commons preservation rather than as monetised toll layers.
This includes obligations that:
- guarantee lifecycle maintenance and durability (preventing premature replacement and waste),
- enforce repairability (parts, documentation, tooling access) as a public-interest constraint,
- maintain service levels and reliability for essential infrastructures,
- impose stewardship duties preventing extraction through degradation.

The key boundary: maintenance counted as C must be **duty-bound and order-preserving** (stable capacity, durable
access), not a proprietary rent channel. If maintenance is accessible only through a proprietary choke point that
enables above-functional pricing, the surplus component belongs in E.

### Conformance requirements (binding)

- C-as-maintenance MUST specify: lifecycle scope, service-level guarantees, repairability constraints, and who bears
  the duty (and under what enforcement).
- If maintenance is monetised via exclusive control (parts, authorization, closed tooling), the toll component MUST
  be split and treated as E.

---

## B00.CH03.P04.S04 — C versus “public ownership”: order-properties prevail over ownership form

C is not defined by ownership form. “Public ownership” is neither necessary nor sufficient for C.

- **Not sufficient:** a publicly owned entity can operate as an extractive gate (tolls, lock-in, opaque fees), in which
  case the extractive components are E.
- **Not necessary:** commons capacity and access can be created via private or hybrid arrangements if order properties
  (open access, non-discrimination, auditability, anti-capture) are binding and enforceable.

Therefore, classification must track **order-properties**:
- does the arrangement expand contestable access and reduce dependence?
- does it increase/stabilise capacity (ΔG) under enforceable governance?
- does it prevent private appropriation or conversion into a toll gate?

### Conformance requirements (binding)

- Any claim that “public ownership” implies C is non-conform unless the order properties and governance regime are
  specified and auditable.
- Any hybrid/private commons claim MUST document anti-capture safeguards, enforceability, and non-appropriation
  constraints; otherwise the claim fails closed for OBA-critical evaluation.
