# B00.CH03.P11 — Measurement and audit standards for P/E/C

This paragraph defines the minimum **measurement** and **audit** standards required for P/E/C classification to be
OBA-grade. P/E/C is normative only insofar as it is **measurable, reproducible, and contestable**.

A P/E/C output is not valid for OBA conformance claims if it cannot be independently reproduced from recorded inputs,
or if it relies on opaque models, undisclosed assumptions, or discretionary interpretation.

Auditability is treated as a hard interface requirement: when the requirements below are not met, the affected
classification must be marked non-auditable and handled under fail-closed rules.

---

## B00.CH03.P11.S01 — Minimum metric set: price/cost, margin bands, lock-in proxies, fee stacks

Any implementation claiming P/E/C classification MUST support, at minimum, the following metric families:

### Price / effective price
- observed price/payment amount (and currency/unit),
- total cost of ownership where relevant (incl. mandatory add-ons),
- hidden price domains where applicable (e.g., data/attention), either modeled or explicitly flagged as unmeasured.

### Cost basis / functional cost proxies
- direct cost estimates where available, or
- auditable proxies (regulated cost-of-service, benchmark costs, input-cost indices, service-level-adjusted comparators).

### Margin bands
- declared “normal margin” bounds per contract type / market structure,
- justification for chosen bounds (benchmarks, regulation, contestable market evidence),
- uncertainty bands where exact margin cannot be determined.

### Lock-in / exit proxies
- switching cost estimates (migration, retraining, compatibility breakage),
- contractual exit penalties, duration/renewal traps,
- portability/interoperability constraints,
- bundling/tying indicators and de facto mandatory add-ons,
- scarcity/essentiality flags where demand is inelastic.

### Fee stacks / chain indicators
- presence of multiple fee layers (platform → payment → affiliate → distributor),
- cascade detection (fees-on-fees, sequential percentage charges),
- pass-through vs markup indicators,
- internal fee/transfer pricing flags (where observable).

### Conformance requirements (binding)

- If an implementation cannot produce this minimum metric set (or declare its absence), it cannot certify P/E/C for
  OBA-conformance purposes.
- Metrics MUST be defined with units, domains, and time resolution; “qualitative only” proxies may be used only where
  they are explicitly declared and conservatively escalated.

---

## B00.CH03.P11.S02 — Audit trail: reproducible derivation of classification per flow/contract

Every P/E/C classification must have an **audit trail** sufficient for a third party to reproduce the result.

Minimum audit trail per classified flow (or flow class) includes:

- flow object identifier and metadata (counterparties, contract type, price rule, time index),
- input metrics used (price, cost/proxies, lock-in proxies, fee-stack indicators),
- rule set/version used (canon version + implementation version),
- decomposition steps (P/E/C split amounts or ranges, reconciliation to total),
- decision points (which criteria triggered: toll, lock-in, claim stack, asymmetry),
- uncertainty representation (bands, coverage flags),
- any overrides/corrections (secondary attribution) with explicit evidence links.

The audit trail must be stable under reproduction: different auditors using the same inputs and rules must obtain
the same classification outcome (within stated uncertainty bands).

### Conformance requirements (binding)

- Black-box classification (uninspectable model outputs, undocumented heuristics, opaque “AI says so”) is non-conform
  where auditability is required.
- If the audit trail cannot be produced for a material component, dependent OBA claims MUST fail closed or be limited
  to the auditable subset with explicit coverage disclosure.

---

## B00.CH03.P11.S03 — Publication requirements: aggregates + methodology + uncertainty reporting

OBA-grade use requires **public reporting** sufficient for contestability and micro→macro reconciliation.

Minimum publication requirements (at least):

- **Aggregates** of P/E/C by relevant dimensions (jurisdiction, sector, cohort, contract type, essential vs non-essential),
- **Methodology**: rule set/version identifiers, metric definitions, margin bounds, and decomposition approach,
- **Uncertainty reporting**: bands, coverage rates, missingness patterns, and sensitivity notes,
- **Reconciliation**: identities that connect micro sums to macro totals (or explicit statement of non-reconciled gaps),
- **Change log**: versioned updates and restatements when methods or data change.

Publication does not require revealing personal data; it requires publishing enough structure to evaluate whether
classification is disciplined and not gamed.

### Conformance requirements (binding)

- An implementation MUST NOT claim OBA compatibility/conformance on the basis of unpublished, non-reviewable P/E/C results.
- Aggregates MUST include uncertainty and coverage; reporting point estimates without uncertainty where uncertainty is
  material is non-conform.

---

## B00.CH03.P11.S04 — Escalation: in doubt classify as E unless explicitly rebutted (conservative)

When evidence is insufficient to safely distinguish functional remuneration (P) from toll extraction (E), the canon
requires **conservative escalation** to prevent OBA-washing.

Canonical escalation rule:

- If a component could plausibly be E and the data needed to rebut E is missing or non-auditable, then:
  - classify the disputed surplus component as **E**, OR
  - mark it **unknown/non-conform** and treat it as non-certifying for OBA claims.
- Classification as **P** in the presence of power/lock-in indicators requires explicit, auditable rebuttal.

This rule applies especially in:
- essentials and inelastic domains (housing/energy/health),
- platform/intermediary structures with fee stacks,
- finance with refinancing lock,
- hidden-price domains (data/attention).

### Conformance requirements (binding)

- Implementations MUST document escalation triggers and outcomes; silent “best effort” assumptions are non-conform.
- Any OBA claim that relies on non-escalated ambiguous components MUST provide the explicit rebuttal evidence; absent
  that evidence, the claim fails closed.
