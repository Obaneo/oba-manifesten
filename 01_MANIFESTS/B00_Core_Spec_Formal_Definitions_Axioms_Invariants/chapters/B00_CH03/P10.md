# B00.CH03.P10 — Relation to caps (W-MAX/I-MAX): E as input, caps as brake

This paragraph specifies the canonical linkage between **P/E/C** and **caps** (**W-MAX**, **I-MAX**).
Within OBA, caps are not a moral add-on; they are an order brake that limits the ability to **store extracted
surplus** as enduring power.

P/E/C provides the upstream diagnostic:
- **E** indicates where surplus is being extracted via power/lock-in/claim stacking.
Caps provide the downstream constraint:
- **W-MAX/I-MAX** limit how much extracted surplus can be accumulated and retained as wealth or income.

The linkage is functional: if caps do not measurably constrain the storage of extraction, they are not OBA-grade.

---

## B00.CH03.P10.S01 — E accumulates in W/I via claim stacks; caps limit the storage

Extraction is not primarily a one-off event; it becomes an order property when it is **stored** as durable claims,
assets, and control. The canonical mechanism is:

- **E → claim stacks → income flows (I) → wealth stocks (W)**

Examples (non-exhaustive):
- monopoly rents and platform tolls become profit flows, then asset valuations;
- interest spreads and fee stacks become compounding claims;
- essential-domain extraction (housing/energy/health) becomes stable cashflow streams, then capitalized wealth.

Caps operate as the brake by limiting:
- the **stock** storage (W-MAX: maximum admissible wealth base under valuation conventions), and
- the **flow** storage rate (I-MAX: maximum admissible income/claim flow into W).

### Conformance requirements (binding)

- Any OBA-cap implementation MUST specify which E channels it constrains (what claim stacks feed W/I, and how the cap
  base captures them).
- If the cap base definition allows extracted surplus to bypass measurement (e.g., via valuation loopholes), the cap
  is non-conform or incomplete for OBA-grade claims.

---

## B00.CH03.P10.S02 — Reallocation rule: cap skimming can be classified as C (under conditions)

Cap enforcement can generate a **skim** (excess above cap) that is removed from private storage. This skim may be
classified as **C** only when it is allocated to commons capacity under enforceable, non-appropriable regimes.

Canonical conditions for “cap skimming = C” include ALL of:

1) **Traceability:** the skim amount is traceably linked from cap computation → collection → allocation.
2) **Non-reversibility:** allocation is not a temporary parking mechanism that can be reclaimed or privatized.
3) **Commons destination:** funds/resources go to defined commons objects (capacity ΔG↑ or ΔG stabilisation, access
   regimes, maintenance duties) with measurable outputs.
4) **Anti-capture safeguards:** governance prevents conversion into new toll gates or patronage extraction.
5) **Auditability:** publication of aggregates + methodology sufficient for reproducible audit.

If any condition fails, the skim is not creditable as C for OBA claims (it may still exist fiscally, but is not a
C classification component).

### Conformance requirements (binding)

- Any C credit claimed from cap skimming MUST publish the allocation regime and audit trail.
- If allocation is discretionary, opaque, or appropriable, C credit MUST fail closed.

---

## B00.CH03.P10.S03 — Ban on cosmetic caps: relabelling that leaves E untouched is non-conform

A “cap” is cosmetic (non-conform) if it changes labels or nominal rates without constraining the underlying E
mechanism.

Non-conform “cosmetic cap” patterns include (non-exhaustive):
- caps that exempt or exclude dominant asset classes or key claim channels where E is stored;
- caps that are easily bypassed by reclassification (salary → capital gains → deferred comp → in-kind);
- caps that ignore valuation conventions, allowing under-reporting of W or hiding of control-equivalent assets;
- caps with enforcement so weak that expected bypass dominates expected constraint.

Canonical test:
- If post-cap, the same power/lock-in structures produce the same tolls and the same accumulation trajectories,
  then the cap is not functioning as a brake under OBA and is non-conform for OBA-grade claims.

### Conformance requirements (binding)

- Cap proposals MUST specify how they reduce E storage in practice; “fairness” narratives are insufficient.
- If the cap does not materially change expected W/I accumulation for the relevant top-tail regimes, it cannot be
  presented as OBA-conform.

---

## B00.CH03.P10.S04 — Link with anti-avoidance: shifts change form but not function (so E remains E)

Anti-avoidance is required because extraction and storage are adaptive: actors will shift **form** to preserve the
same **function** (toll extraction and storage).

Canonical rule: **substance over form**
- If a structure changes legal form, accounting form, or instrument type without changing the functional effect
  (power/lock-in sustained tolls and claim storage), then:
  - the **E classification remains E**, and
  - the cap base must capture the shifted equivalent.

This includes (non-exhaustive):
- income deferral and conversion (salary → equity → carried interest → loans → offshore vehicles);
- asset re-wrapping (ownership → control rights → derivatives → trusts → SPVs);
- cross-border shifting and internal transfer pricing that relocates surplus without changing extraction mechanics;
- bundling/unbundling tactics that preserve the same effective toll.

### Conformance requirements (binding)

- Any OBA-cap implementation MUST include anti-avoidance equivalence rules that track functional control and claim
  storage, not nominal categories.
- If anti-avoidance coverage is missing for a plausible bypass path, OBA claims MUST fail closed on the affected
  component (or disclose the bypass as a non-conformance risk).
