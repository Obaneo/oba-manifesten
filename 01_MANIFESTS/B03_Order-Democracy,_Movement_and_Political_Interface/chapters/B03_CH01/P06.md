# B03.CH01.P06 — Reading and decision route through Book 3

This paragraph provides the **navigation logic** of Book 3: the order in which concepts should be read, and the order in which
political decisions should be taken, so that mandates, institutions, commons governance, movement dynamics, and forks remain
**consistent** with the Kernel Spec and with OBA’s non-negotiables. The route is designed to prevent “starting from rhetoric” and
ending in drift: it forces the reader to move from **mandate criteria** to **implementable institutional rails**, then to **commons
operations**, then to **movement interface**, and only then to **fork/compatibility outcomes**.

---

## B03.CH01.P06.S01 — Mandate → institutions → commons governance → movement → forks

Book 3 is read as a dependency chain: each layer constrains the next, and later layers cannot redefine earlier ones.

### Route (dependency order)
1. **Mandate (CH03)**: what is authorised, by whom, under which order criteria.
2. **Institutions (CH05 + CH10)**: separation of functions, auditability, enforcement, anti-capture.
3. **Commons governance (CH04)**: access, maintenance, scarcity rules, dispute resolution within rails.
4. **Movement/support structures (CH06)**: how implementation is sustained politically without ideology drift.
5. **Forks/compatibility (CH07)**: formal classification when pluralism requires divergence.

### Conformance requirements (binding)
- Policy proposals MUST be evaluated in this order; a later layer MUST NOT be used to retroactively justify breaking earlier rails
  (e.g., “movement necessity” cannot override auditability).
- Any deviation that touches constitutive rails MUST be routed to the fork/compatibility procedure (CH07), not handled as an
  ad-hoc exception.

---

## B03.CH01.P06.S02 — Democratic consistency test as the capstone (B03.CH12)

The reading route terminates in a **single pass/fail governance test** that decides whether the system remains OBA-compatible in
practice, not just in rhetoric.

### Capstone role
- Aggregates signals from mandate design, institutional performance, commons governance, and anti-capture.
- Converts diffuse drift into **formal outcomes**: compatible / partially compatible / incompatible, with escalation requirements.

### Conformance requirements (binding)
- Governance MUST treat B03.CH12 as the binding capstone: if the test fails, remediation/rollback paths are mandatory.
- The consistency test MUST be run on a defined cadence and after major shocks/changes (emergency regimes, definition-set changes,
  large procurement shifts).

---

## B03.CH01.P06.S03 — Interface with Book 4: cognitive order as a precondition for democracy

Book 3 assumes that democratic contestability depends on **cognitive order**: shared definitions, stable metrics, and an information
environment where citizens can evaluate claims.

### Interface logic
- Book 4 supplies constraints on information integrity: definition hygiene, epistemic discipline, and anti-confusion rails.
- Book 3 consumes these as prerequisites for legitimacy (e.g., contestability requires intelligible, stable evidence).

### Conformance requirements (binding)
- If cognitive-order prerequisites are not met (definition chaos, metric gaming, reproducibility collapse), governance MUST treat
  this as a legitimacy incident and MUST trigger enhanced audit/repair.
- Public communication in Book 3 domains MUST follow Book 4 discipline: versioned definitions, source duty, and restatements where
  corrections occur.

---

## B03.CH01.P06.S04 — Interface with the Kernel Spec: where definitions and calculation rules live

Book 3 is a political/governance book. It does not host canonical definitions or computation rules; it **references** them.

### Source hierarchy
- **Kernel Spec**: canonical objects, definitions, invariants, tests, and calculation rules.
- **Book 3**: mandate/governance logic, institutional design constraints, and political interfaces that *must* point back to Kernel.

### Conformance requirements (binding)
- Any paragraph in Book 3 that uses canonical terms MUST reference the Kernel Spec definition-set and version as the source of
  meaning (no redefinition by paraphrase).
- If Book 3 text conflicts with the Kernel Spec, the Kernel Spec prevails and Book 3 MUST be corrected (anti-drift rule).
