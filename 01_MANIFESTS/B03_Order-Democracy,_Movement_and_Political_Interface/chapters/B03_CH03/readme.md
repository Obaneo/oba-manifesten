# B03.CH03 — Legitimacy and mandate: from electoral logic to order criteria

This chapter defines **mandate** and **legitimacy** in OBA order-democracy as **testable, auditable governance claims** rather
than rhetorical authorisation. Elections can set direction and priorities, but they are not sufficient to legitimise decisions that
affect **constitutive rails** (caps bindingness, commons access/maintenance, measurability/auditability, contestability, and ΔM
allocation integrity). The chapter therefore introduces **mandate types** keyed to **order impact**, and a legitimacy framework that
binds political authority to **evidence discipline**, **procedural contestability**, **distributional floors (R/B)**, and
**compatibility with non-negotiables**.

It also defines how mandates are **granted**, how political promises are translated into **testable assignments** (with uncertainty
bands and anti-gaming rules), how conflicts between mandates are resolved without semantic drift, and how mandate execution is
protected against **capture**, **vendor lock-in**, and **relabeling**. Finally, it treats mandate as a **repeatable contract** with
midterm checks, ex post audits, and explicit re-authorisation thresholds.

## How to use this chapter

- If you are drafting **policy programmes or coalition agreements**: express commitments as **mandate text in test axes**
  (E, caps, commons/ΔG, R/B, ΔM) and include **audit hooks** (logs, scorecards, escalation triggers).
- If you are designing **institutions (Book 3/5)**: use the mandate-type distinctions to allocate powers and set
  **supermajority/dual-key** requirements for constitutive changes.
- If you are evaluating whether a government action is **legitimate under OBA**: apply the five legitimacy criteria and check
  whether the action matches the correct mandate type (parametric vs constitutive vs emergency, etc.).
- If you are handling **mandate disputes**: use the conflict rules to prevent “technical” bypasses, exception stacking, and
  informal fork creation; escalate to formal compatibility/fork labeling where needed.

## Structure

P01 — Problem statement: electoral logic is insufficient for order decisions  
P02 — Mandate types: distinctions by order impact  
P03 — Legitimacy criteria: procedural, epistemic, distributive, institutional, substantive  
P04 — Mandate granting: elections, referenda/conventions, supermajority/dual-key, minority/generational rails  
P05 — Mandate operationalisation: test axes, anti-gaming KPIs, sequencing, exception discipline, scorecards  
P06 — Mandate conflicts: priority rules, commons vs market boundaries, crisis vs rule of law, fork decision  
P07 — Mandate protection: disclosure, anti-lock-in, function-over-label, audit of execution, sanctions for breach  
P08 — Evaluation and re-authorisation: midterm checks, ex post audits, version control, public accountability  

## Status

This chapter is **normative** for how OBA governance treats political authority. Any implementation claiming OBA alignment must be
able to show: (i) which mandate type authorises each decision domain, (ii) how legitimacy criteria are satisfied with evidence and
contestability, and (iii) how re-authorisation and rollback occur when mandates expire, conflict, or drift. Changes to this chapter
must preserve the binding character of mandate types and legitimacy criteria, and must be traceable via changelog and restatement
discipline.
