# B05.CH01 — Kernel: the lifeworld layer as a test (from macro-invariants to experienced GROSS/NET/BURDENS)

This chapter defines the **lifeworld layer** as a **binding test interface** between the macro order (invariants, classification,
channels, caps) and what households can actually experience, contest, and verify. Its purpose is not to “tell stories about people,”
but to make claims executable as **tests**: if an implementation says it reduces extraction, restores residual space, improves commons,
or neutralises clamp mechanics, the lifeworld layer specifies what must become observable, publishable, and disputable.

CH01 is explicitly **anti-washing** and **anti-drift**:
- It translates canonical macro constructs into minimal household-observable quantities and proxies.
- It requires publication and reproducibility (definition-set + method IDs, uncertainty discipline, restatements).
- It treats narrative as non-evidence unless linked to measurement outputs and re-executable test instances.
- It fails closed: if the test cannot be executed under privacy and capacity constraints, compatibility cannot be claimed.

## How to use this chapter

- If you are **evaluating compatibility**: use CH01 as the checklist for whether macro claims are grounded in observable experience
  (B/T/N/L/R mappings, lock-in proxies, publication tables, dispute rails).
- If you are **designing measurement**: implement the minimal “experience set,” privacy minimalism, join-safety constraints, and the
  reproducibility package (definition-set ID, method_id, uncertainty, revision policy).
- If you are **building institutions**: treat CSA as the correction loop, and design contestability, escalation, and audit triggers
  so that lived signals can force schema review and remedy pipelines.
- If you are **writing cases (sector / day-in-the-life)**: use the templates and case structure; narratives must bind to published
  tables and causal chains, not replace them.

- **Do not introduce new definitions** here for canonical constructs (P/E/C, ΔM, caps, B/T/N/L/R, α, etc.).
- Always **reference** the canonical definition set (definition-set ID + version) and treat CH01 as a translation + test layer.

## Status

This chapter is **normative** for any implementation that claims people-level validity. If CH01 outputs cannot be produced as public,
reproducible artifacts (within privacy and execution capacity rails), the implementation MUST be treated as **incomplete** and MUST
fail-closed (no lifeworld-compatibility label). Failure modes in P12 are treated as **systemic drift risks** and should trigger CSA
escalation, schema review, and, where necessary, incompatibility or relabeling.
