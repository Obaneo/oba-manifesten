# B05.CH18.P20 — Close: stop rules and minimal repair paths

This paragraph defines the **stop rules** and **minimal repair paths** that make CH18 enforceable. Stop rules are not recommendations;
they are binding gates that prevent “muddling through” when lifeworld integrity, privacy, or legitimacy is breached. Each stop rule has:
(i) trigger conditions, (ii) scope of scaling halt or rollback, (iii) mandatory actions, and (iv) recertification requirements.

---

<a id="b05ch18p20s01"></a>
## B05.CH18.P20.S01 — Stop rule A: rising essentials-L or worsening tails without an external shock → halt scaling

### Trigger condition (binding)
Stop rule A triggers when, within a defined window, any of the following holds for one or more target cohorts:
- `essentials_L_rises` beyond uncertainty bands, or
- `tails_worsen` (arrears/lockouts/wait-time exceedances/cost spikes rise), or
- `time_friction_worsens` (cycle times/drop-off/appeal backlog rise),
**AND** the `external_shock_exclusion_check` is negative (no qualifying external shock).

### Mandatory action set (binding)
- `halt_scaling`:
  - stop expansion of the affected domain (no new rollouts, no widening eligibility, no new procurement scale-up)
- `scope_restriction_if_needed`:
  - fail-closed to auditable coverage if capacity is insufficient
- `initiate_forensic_review`:
  - identify which mechanism dominates (bottleneck, E stack, procedure drift, sabotage)
- `deploy_interim_relief`:
  - prevent irreversible harm (no disconnections/evictions/lockouts escalation while repair is underway)

### Recertification (required)
Scaling can resume only after:
- post-repair dashboards show L/tails/time metrics back within thresholds, and
- method/version restatements are published (aggregated), and
- audit confirms non-selective enforcement for the affected domain.

### Conformance tests (minimum)
- **STOP-A-01 (Shock check):** external shock exclusion logic is present and logged.
- **STOP-A-02 (Real halt):** halt scope is defined and actually blocks expansion actions.

<a id="b05ch18p20s02"></a>
## B05.CH18.P20.S02 — Stop rule B: privacy/integrity breach (silent edits, unsigned changes, scope creep) → immediate rollback

### Trigger condition (binding)
Stop rule B triggers immediately upon any of the following:
- `integrity_breach`:
  - silent edits, unsigned changes, tamper-evidence failure, missing lineage, signature mismatches
- `privacy_breach`:
  - join-safety violation, microdata publication, unauthorized access, unlogged data expansion
- `scope_creep_without_necessity`:
  - identity linkage expansion or secondary use without logged necessity and approvals

### Mandatory action set (binding)
- `immediate_rollback`:
  - revert to last known-good version of affected templates/methods/tooling
- `freeze_high_risk_changes`:
  - stop further edits/updates until integrity is restored
- `preserve_evidence`:
  - secure logs, hashes, and auditpacks; prevent tampering
- `publish_incident_summary` (aggregated):
  - what happened, severity, time-to-containment, and next steps
- `root_cause_audit`:
  - independent forensic audit of the breach and controls failure

### Recertification (required)
Resumption requires:
- verified restoration of tamper-evidence and signed change control,
- privacy rail revalidation (aggregation/suppression/join safety),
- published restatement and governance remediation.

### Conformance tests (minimum)
- **STOP-B-01 (Auto-rollback):** integrity/privacy triggers map to automatic rollback actions.
- **STOP-B-02 (No silent edits):** change control requires signing + logging + version bump; violations are detectable.

<a id="b05ch18p20s03"></a>
## B05.CH18.P20.S03 — Stop rule C: proven selective enforcement or capture → governance reset + conformance suspension

### Trigger condition (binding)
Stop rule C triggers when selective enforcement or capture is **proven** under CH18 evidence standards (P15), including:
- repeated exceptions benefiting the same positions without general rule basis,
- audit suppression or missing incident disclosure,
- procurement/tooling dominance that defeats auditability,
- confirmed enforcement parity breaches without lawful rationale,
- revolving-door violations coincident with procurement/exception outcomes.

### Mandatory action set (binding)
- `conformance_suspension`:
  - suspend conformance claims for the affected domain (publicly, aggregated)
- `suspend_discretionary_powers`:
  - freeze discretionary exception granting; revert to default rule paths
- `governance_reset`:
  - role rotation, separation enforcement, meta-audit activation, exception purge
- `procurement_reset` (if implicated):
  - tooling unbundling, open standards mandates, exit assistance
- `forensic_audit_and_publication`:
  - publish aggregated findings and the reset plan

### Recertification (required)
Conformance can resume only after:
- reset actions are completed,
- audit-on-the-auditor confirms reduced skew and restored transparency,
- exception patterns normalize within thresholds,
- dashboards confirm lifeworld integrity not worsening.

### Conformance tests (minimum)
- **STOP-C-01 (Suspension is real):** suspension blocks discretionary actions and public conformance statements.
- **STOP-C-02 (Reset completeness):** governance reset includes rotation + exception handling + procurement/tooling remediation where relevant.

<a id="b05ch18p20s04"></a>
## B05.CH18.P20.S04 — Repair path: forensic audit → restatement → template redesign → recertification (no “muddling through”)

### Minimal repair path (binding sequence)
1) `forensic_audit`:
   - reconstruct lineage; identify root mechanisms; produce evidence-based findings
2) `restatement`:
   - correct data/methods/decisions; publish aggregated restatement with version references
3) `template_redesign`:
   - change the actual substrate (contracts, procedures, channel classifications, governance roles)
4) `retest`:
   - run dashboards and regression cases (CH14–CH16; CH17 sector checks) under the new version
5) `recertification`:
   - independent audit confirms integrity/privacy/contestability + lifeworld improvements within thresholds
6) `deprecation`:
   - deprecate old templates/clauses/channels; migrate users; prevent shadow legacy persistence

### Required repair artefacts (minimum)
- `audit_report_ref` (aggregated public summary + restricted evidence pack list)
- `restatement_ref` (what changed, why, before/after deltas with uncertainty)
- `change_set_ref` (template/method/benchmark versions)
- `retest_results_ref` (dashboards + regression tests)
- `recertification_ref` (status decision with reason codes)
- `deprecation_plan_ref` (migration, sunsets)

### Normative requirements (RFC 2119)
- Repair **MUST** be substrate change (templates/procedures/channels), not training or messaging.
- Repair **MUST** be time-bounded; open-ended remediation is drift risk.
- Without recertification evidence, scaling **MUST NOT** resume.

### Conformance tests (minimum)
- **REPAIR-01 (Sequence discipline):** repair follows audit→restatement→redesign→retest→recertify.
- **REPAIR-02 (Deprecation):** old artifacts are deprecated with migration paths.

---

### Output format (stop-rule register)

At minimum, CH18 **MUST** emit a stop-rule register (table or structured list) with:

- `stop_rule` | `trigger_indicator_ref` | `threshold_or_condition` | `external_shock_check` | `action_scope` |
  `mandatory_actions` | `recertification_criteria` | `status`

If stop rules are not explicit and actionable, CH18 becomes advisory and Book 5 becomes non-enforceable.
