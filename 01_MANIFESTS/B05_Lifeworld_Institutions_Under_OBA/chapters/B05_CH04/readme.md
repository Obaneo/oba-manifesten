# B05.CH04 — Security and buffers: income floor, risks, shocks, insurance, and fallback commons

This chapter specifies the **security and buffer architecture** required for lifeworld stability under OBA. Its function is not
charity and not paternalistic discipline; it is **tail-risk control**: preventing small shocks and structural volatility from
cascading into arrears, debt spirals, forced lock-in, and loss of exit power. Security is treated as infrastructure that stabilises
**R/B tails** while refusing to open new extraction channels through insurance clamp, fee-stacks, surveillance, or discretionary
political deals.

CH04 is explicitly **fail-closed**:
- If security requires humiliation, control, or invasive monitoring to function, it is non-conforming.
- If buffers are routed through private fee-stacks or lock-in contracts, they are treated as E-regrowth and must be neutralised.
- If “emergency regimes” become permanent or turn into asset/claim support (ΔM leakage), they trigger hard stops.

## How to use this chapter

- If you are **designing an income floor or social protection**: use CH04 to bind the floor to tail outcomes (share_below_alpha,
  volatility, arrears) and to prevent bureaucratic tolling and stigma from becoming hidden L.
- If you are **designing insurance/benefits**: use CH04 to distinguish risk pooling (P) from premium/claims manipulation (E) and to
  require contestability, transparency, and anti-lock-in rails.
- If you are **building shock response**: use CH04 to define trigger criteria, sunset discipline, unwind plans, and forbidden ΔM
  channels (no asset/claim support by stealth).
- If you are **auditing security claims**: use the measurement/publication requirements and failure modes to detect selective
  execution, administrative clamp, fee-stack capture, and “moral hazard” rhetoric used to block L reduction.

## Status

This chapter is **normative** for any implementation claiming lifeworld compatibility. Security and buffers are constitutive for
stability: if tails worsen, if arrears/debt cascades grow, or if access becomes conditional on control and humiliation, the order is
drifting toward incompatibility. In such cases, CH04 requires escalation: redesign of instruments, rollback of harmful conditionality,
requalification of fee-stacks, and—where necessary—temporary scope reduction to what can be executed under auditability and privacy
constraints.
